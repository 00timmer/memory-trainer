# Memory Trainer 编码速度训练

单文件 HTML 记忆训练器。所有数据存在浏览器 localStorage，无后端、无账号。

**在线使用：** https://00timmer.github.io/memory-trainer/

## 三个训练系统

| 系统 | 问题 | 状态 |
|---|---|---|
| **C 提取自动化** | 已经知道的东西，取得多快 | ✅ 已上线 |
| **A 直接记忆** | 看一遍/听一遍，能留下多少 | ✅ 视觉 + 听觉 + 保持曲线已上线 |
| **B 快速编码** | 需要用方法时，建立稳定记忆有多快 | P5 待做 |

三个指标**分开显示，不合成总分**——它们改善速度不同。

设计与取舍见 [DESIGN.md](DESIGN.md)。

## 当前版本做了什么（P0–P2，2026-09-08）

**计时口径重建。** 旧版记的是「出题 → 点评分」的总时长，里面混了 F1 强制 3 秒等待、
翻牌后 0.5/1/1.5 秒锁定、以及读答案和点按钮的时间。现在是：

```
cue 出现 → 想到答案按键（延迟在此冻结）→ 显示答案 → 核对对错
```

核对时间完全不计入。切到后台的试次自动作废。

**删除了速度惩罚。** 旧版 `revealTooFast` 会因为你答得快而加大阻力，
还会按用时建议你选「模糊」。秒答正确就是成功，不再被惩罚。

**校准试次（默认 20%）。** 按键后不直接给答案，先要求 4 选 1。
用来检查「按键后再看答案判对」有没有在放水——仪表盘会对比自评正确率与校准实测正确率。

**「不会」给足反馈时间。** 旧版显示答案后同步跳下一张，答案可能都没画出来。
现在必须手动点继续，并且这张卡会隔 3–5 张重新出现。

**掌握度按提取方向分开。** 正向 / 反向 / 连读各自独立记账。
四态：未测 → 能正确提取 → 能快速提取 → 隔天仍能快速提取。

**弱项分两类。** 错项（想不起/答错）和慢项（对但持续慢）分开追踪、分开训练。
连读答错时可以指出到底哪几个没答上，不再一起判错。

**到期复习真正启用。** 旧版算了 `nextReview` 但抽题时从不读。

**冲刺超时单独记录。** 超时后才想起来的，不算限时成功。

**「今日训练」一键开练。** 自动按 到期 > 错项 > 慢项 > 混淆对 > 已掌握项抽查 编排，
5 / 15 / 20 分钟三档。原有 9 种模式收进折叠区，保留不变。

**数据导出/导入。** localStorage 不跨设备，定期导出 JSON。

## 直接记忆（P3，2026-09-10）

呈现一次 → 隐藏 → 自主回忆。回忆阶段**不给任何选项**，是回忆不是再认。

**两类材料。** 随机汉字序列（长度自适应）和有意义材料（短句 → 长句 → 两句 → 短段落）。

**四项分开打分。** 有意义材料自动算逐字（编辑距离）、关键词（命中率）、顺序（关键词的相对次序），
大意由你自评三档。随机序列把「记住的字」和「位置正确」分开算——项目记忆和顺序记忆是两回事，
字全记住但顺序错，和根本没记住，是不同的问题。

**难度按块调整。** 每 5 个试次调一次，>90% 升、<60% 降，不因单次运气变动。

**标准化基线。** 3/4/5/6/7 项各 5 次，曝光锁死 3.0 秒，不自适应。输出直接记忆容量
（维持 77.5% 正确率的最大长度，在曲线上插值）。条件不同的两次基线**拒绝比较**——
改了曝光时长或长度集合，数字就没有意义。

**今日训练分段。** 15/20 分钟 = 直接记忆 5 分 + 提取剩余时间；5 分钟速练不含直接记忆
（一个有意义材料试次就要一分钟，塞不下）。

> ⚠️ 随机序列的容量训练**迁移有限**——练随机汉字串主要提升的是随机汉字串本身的成绩，
> 不太会迁移到生词、诗词、歌词。判断整体记忆是否变好，看有意义材料和（P4 的）听觉那几项。
> App 里在仪表盘和每轮结束页都写了这句话。

## 听觉直接记忆与保持曲线（P4，2026-09-10）

**听一遍，不显示文字，不能重放。** 数字串（听觉广度）和语音材料（短语 → 句子 → 两句 → 段落）
两条独立阶梯，和视觉那两条完全分开记账、分开调难度。语音播放失败的试次**作废**，不记成答错。

语速会被记录。**改了语速，前后的听觉成绩就不能比**——仪表盘检测到混用会直接警告。

**保持曲线。** 学过的有意义材料自动排进 30 秒 / 5 分钟 / 24 小时 / 3 天 / 7 天五档队列，
下次训练开头优先补测（一轮最多 8 项）。测试时**只给开头三个字当线索，绝不重新呈现原文**——
否则测的是重学不是保持。线索里的那几个字和落在线索里的关键词都从评分里剔除。

**按真实经过时间分桶，不按标称档位。** 标称 24 小时但你隔了 4 天才打开，就记到「3 天」那一桶。
纯网页没有推送，到期只能靠你下次打开时补——所以档位名不可信，真实间隔才可信。

## 摩尔斯电码（2026-10-23）

新内置牌组 **📡 摩尔斯电码**，用已有的数字桩记：`1 = ·（嘀）`、`2 = —（嗒）`，
11 路飞 / 12 特兰克斯 / 21 香蕉鳄鱼 / 22 17·18 号。不是独立小工具，直接接进 System C 的计时和掌握度：

| 训练 | 用哪个模式 | 记在哪个方向 |
|---|---|---|
| 字母 → 编码 | 随机闪卡 | 正向 |
| 编码 → 字母 | 反向闪卡 | 反向 |
| 1 秒内识别 | 冲刺挑战（看延迟分档，< 0.8s 为自动） | 正向 |
| 听嘀嗒 → 字母 | 摩尔斯面板「🔊 听音识字母」 | 听音（独立记账） |
| 单词解码 / 听单词 / 单词编码 | 摩尔斯面板 | 按单词记账，不污染单字母统计 |

- **分组推进**：四组（ETIANM / 3 位 / 4 位 / 数字）。第一次进入时所有模式的范围默认只有第一组；
  面板显示每组「能正确 / 能快速」，组内全部能快速再加下一组。
- **听音的延迟从「播完」开始算**，播放中不能按键——否则长字母天然吃亏。Web Audio 合成，APK 里也能用
  （和 Web Speech 不同）。字符速度 10–25 WPM，字母间距放宽到 6 单位方便初学。改了 WPM 前后不可比。
- **故事只是过渡**：「答案下显示故事」学习期开着；熟练后切成「只在答错时显示」。答错（不会 / 自评错 /
  校准选错）**一定**提示正确编码 + 桩故事。永远不考故事本身。
- **单词只从当前字母范围里出**，只学了 ETIANM 也能练 TEAM、MEAT、TIME 等；拼不出 5 个单词时拒绝开始。
- **分组口诀**（2026-10-27）：第一组 = **INMATE**，第二组 = **DUG WORKS / DUSK GROW**（单词只帮记「哪些字母在这一组」）。
  能直接推出编码的是按前两位数字桩排的顺序：第二组 **SU · RW · DK · GO**（每对前 +1 后 +2），
  第三组 **HVF · LPJ · BXCY · ZQ**（空格 1122 / 1212 / 2221 / 2222 没有英文字母）。面板每组下显示口诀，
  「📖 故事表」每组前有完整的「数字桩 × 后缀」表。表是从编码算出来的，测试会核对口诀和表一致。
- **混淆对**用镜像和反相：A/N、D/U、G/W、K/R、B/V、F/L、Q/Y、X/P 等，「易混淆对」模式可直接练。
- **故事接上字母桩**（2026-10-27）：26 个故事统一成「数字桩按编码顺序出场 → 最后落到字母自己的字母桩」，
  如 A = 12「特兰克斯一剑劈开苹果，砸中牛顿」、B = 21+11「香蕉鳄鱼咬住路飞，熊冲过来抢蜂蜜」。
  三位编码单个信号在开头说「先…」、在结尾说「最后…」，镜像对 W/G、D/U 不会讲成同一句话。
  **Y 例外**：字母桩特兰克斯就是数字桩 12，会让 2122 被误还原出一个 12，所以 Y 落到「时间机器」。
  「📖 故事表」每条附原版。

## 字母编码（2026-10-23）

新内置牌组 **🔤 字母编码**：你自己的字母桩，26 个大写（A 牛顿、B 熊 … Z 兔子警官）+ 小写 a–g
（a 马斯克、b 宠物狗、c 砂糖、d 神笔马良、e 梅利号、f 马红骏、g 川普）。小写 h 还没定，暂不收录。

- **答案只放桩**（牛顿），桥接词（Apple）在揭晓后作为提示出现 —— 放进答案的话，反向卡「牛顿 → ?」会被 Apple 直接泄题。
- 大小写是两套桩，分开记账；「易混淆对」练的就是同字母的大小写（A/a … G/g）。
- 和 0–99 数字桩有交叉的（I 青雉 = 00、F 鸣人 = 09、Y 特兰克斯 = 12、X 雏田、N 甘福尔、c 砂糖、g 川普）保持同一个形象。

## 开发

源码在 `src/`，构建产物是单文件 `index.html`（GitHub Pages 和 APK 都用它）。

```sh
./build.sh          # 拼接 src/ → index.html，纯 shell + python3，无 npm
./run-tests.sh      # 跑自测套件（构建 → headless Chrome → 全通过时退出码 0）
```

改代码后先跑 `./run-tests.sh`，再 commit。

`src/base.html` 是原始应用，新模块按文件名顺序追加：

```
20-store.js      存储 / 迁移 / 导出导入
30-retrieval.js  System C 数据层
40-flow.js       闪卡流程（承诺 → 冻结 → 核对）
42-deck-select.js 顶部牌组下拉
45-morse.js      摩尔斯牌组 / 听音 / 单词 / 故事
46-letters.js    字母编码牌组
50-scheduler.js  今日训练编排
60-dashboard.js  仪表盘 + 自动化地图
90-init.js       路由 / 首页 / 初始化
```

旧 localStorage key 一个不删，随时可以回滚到重构前的版本而不丢数据。

## 测试

`tests/suite.js` 是 122 条断言的自测套件，`run-tests.sh` 把它注入构建产物、
在 headless Chrome 里跑一遍、有任何 FAIL 就以非零码退出。覆盖：

| 分组 | 内容 |
|---|---|
| P0 存储与迁移 | 新旧 key 隔离、旧 level 3 只映射到「能正确提取」、迁移幂等、导出格式 |
| P1 计时口径 | 延迟只含 cue→按键、承诺后计时停住、无强制等待、秒答不被罚、后台/超时试次作废、试次上限、P90 |
| P1 状态机与弱项 | 四态阶梯、答错清空隔天累计、慢项与错项分离、两种毕业条件、方向隔离、到期调度 |
| P1 闪卡流程 | 「不会」必须手动继续、重排只发生一次、校准试次选项与标记、连读逐项判错 |
| P2 编排与仪表盘 | 今日训练优先级与预算、弱项模式含慢项、分布分母、校准放水检测、渲染 |
| P3 材料与评分 | 序列不重复、材料不重取、项目/位置分离、重复凑数不加分、逐字/关键词/顺序独立 |
| P3 直接记忆流程 | 呈现后清空、回忆不给选项、逐格核对、想不起来记 0 分、大意必须自评、延迟队列 |
| P3 自适应与基线 | 块级调整、中间区间不动、基线条件锁死、基线不污染自适应、容量插值、条件不同拒绝比较 |
| P3 今日训练分段 | 分段构成、段间自动衔接、两类材料都有 |
| P4 延迟保持队列 | 五档入队、到期才取、积压优先、真实间隔分桶、同材料去重、不自我循环、不污染即时表、补测限额 |
| P4 听觉直接记忆 | 全程不显示原文、数字串念法、无重放、播放失败作废、语音不可用时拒绝开始、模态隔离、语速警告 |
| 摩尔斯电码 | 36 个编码对照国际表、拆分拼回原码、故事里数字桩按顺序出场且字母桩在最后、Y 避开特兰克斯、镜像对故事不同、默认范围、故事显示规则、听音延迟从播完算、播放中不能按键、单词限范围、单词不进旧弱项表 |
| 字母编码 | 33 个编码、h 不收录、答案不含桥接词、揭晓后才提示、大小写分开记账 |
| 顶部牌组下拉 | 隐藏牌组不出现、选中即切换、摩尔斯面板随牌组显隐 |

套件本身做过变异测试：把 24 个错误行为分别注回代码，确认每个都被对应的断言抓住。
包括「延迟重新包含核对时间」「不会后自动跳下一张」「正反向合并记账」「慢项不进弱项」
「不要求隔天就判满级」「重复的字反复计数」「大意没自评也能继续」「基线污染自适应」
「单次成绩就调难度」「不同条件的基线判为可比」「按标称档位分桶」「同材料重复补测」
「听觉呈现时把原文也显示出来」「语音失败记成答错」「听觉视觉共用难度阶梯」「摩尔斯播放中允许按键」「听音延迟包含播放时间」「单词进旧弱项表」等。

有两条断言第一次没抓住，都是样例选得不够刁：
「多写的字不会刷高正确率」用的样例在两种实现下结果一样，补了「同一个字写三遍」才抓到；
「线索不算进逐字分」的阈值定得太松（0.25），两种实现都能过，收紧到 0.05 并加上
「线索里的关键词要从分母剔除」才抓到。变异测试的价值就在这——它会告诉你哪条断言其实是摆设。
