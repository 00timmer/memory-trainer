# Memory Trainer 编码速度训练

单文件 HTML 记忆训练器。所有数据存在浏览器 localStorage，无后端、无账号。

**在线使用：** https://00timmer.github.io/memory-trainer/

## 三个训练系统

| 系统 | 问题 | 状态 |
|---|---|---|
| **C 提取自动化** | 已经知道的东西，取得多快 | ✅ 已上线 |
| **A 直接记忆** | 看一遍/听一遍，能留下多少 | P3 待做 |
| **B 快速编码** | 需要用方法时，建立稳定记忆有多快 | P5 待做 |

三个指标**分开显示，不合成总分**——它们改善速度不同。

设计与取舍见 [DESIGN.md](DESIGN.md)。

## 当前版本做了什么（P0–P2，2026-09-08）

**计时口径重建。** 旧版记的是「出题 → 点评分」的总时长，里面混了 F1 强制 3 秒等待、
翻牌后 0.5/1/1.5 秒锁定、以及读答案和点按钮的时间。现在是：

```
cue 出现 → 想到答案按键（延迟在此冻结）→ 显示答案 → 核对对错
```

核对时间完全不计入。切到后台的试次自动作废。

**删除了速度惩罚。** 旧版 `revealTooFast` 会因为你答得快而加大阻力，
还会按用时建议你选「模糊」。秒答正确就是成功，不再被惩罚。

**校准试次（默认 20%）。** 按键后不直接给答案，先要求 4 选 1。
用来检查「按键后再看答案判对」有没有在放水——仪表盘会对比自评正确率与校准实测正确率。

**「不会」给足反馈时间。** 旧版显示答案后同步跳下一张，答案可能都没画出来。
现在必须手动点继续，并且这张卡会隔 3–5 张重新出现。

**掌握度按提取方向分开。** 正向 / 反向 / 连读各自独立记账。
四态：未测 → 能正确提取 → 能快速提取 → 隔天仍能快速提取。

**弱项分两类。** 错项（想不起/答错）和慢项（对但持续慢）分开追踪、分开训练。
连读答错时可以指出到底哪几个没答上，不再一起判错。

**到期复习真正启用。** 旧版算了 `nextReview` 但抽题时从不读。

**冲刺超时单独记录。** 超时后才想起来的，不算限时成功。

**「今日训练」一键开练。** 自动按 到期 > 错项 > 慢项 > 混淆对 > 已掌握项抽查 编排，
5 / 15 / 20 分钟三档。原有 9 种模式收进折叠区，保留不变。

**数据导出/导入。** localStorage 不跨设备，定期导出 JSON。

## 延迟分档

| 区间 | 状态 |
|---|---|
| > 3.0s | 卡壳 |
| 2.0–3.0s | 慢 |
| 1.2–2.0s | 流畅 |
| 0.8–1.2s | 快 |
| < 0.8s | ⚡ 自动 |

< 0.8s 已接近简单反应时下限，到这里之后目标从「更快」改为「压低 P90」。

## 开发

源码在 `src/`，构建产物是单文件 `index.html`（GitHub Pages 和 APK 都用它）。

```sh
./build.sh          # 拼接 src/ → index.html，纯 shell + python3，无 npm
```

`src/base.html` 是原始应用，新模块按文件名顺序追加：

```
20-store.js      存储 / 迁移 / 导出导入
30-retrieval.js  System C 数据层
40-flow.js       闪卡流程（承诺 → 冻结 → 核对）
50-scheduler.js  今日训练编排
60-dashboard.js  仪表盘 + 自动化地图
90-init.js       路由 / 首页 / 初始化
```

旧 localStorage key 一个不删，随时可以回滚到重构前的版本而不丢数据。
